# Domain context

## LoginSession / 登录会话

可由服务端撤销的登录状态，一个用户可在多个设备上拥有独立会话。

## AccessToken / 访问令牌

用于访问受保护接口的短期凭证。

## RefreshToken / 刷新令牌

用于延续登录会话的长期、单次轮换凭证。

## Activity / 活动

本系统中的活动，可包含多条外部 Keep 路线。活动通过稳定的 `code` 暴露给 API；具体
路线由 ActivityRoute 的 `keep_route_id` 与 Keep 对接。

## ActivityRoute / 活动路线

活动中可独立完成的一条 Keep 路线。每条路线完成后最多发放一次抽奖机会。

## ActivityRouteCompletion / 路线完成记录

按“Keep 账号 × 活动路线”记录完成状态和抽奖机会发放状态。同一路线重复同步不会重复
发放机会；不同路线分别完成时分别发放。

## ActivityParticipation / 活动参与记录

Keep 账号参与某个活动的汇总状态，包含是否完成过任一路线和当前可用抽奖次数。同一 Keep
账号在同一活动中只能有一条记录；路线明细由 ActivityRouteCompletion 保存。

## KeepAccount / Keep 账号

经 Keep 用户凭证实时验证的活动身份。保存最近确认的公开资料和可用于短期故障复现的凭证，
是活动参与、抽奖和领奖的身份主体。

## LotteryChance / 抽奖机会

完成一次符合条件的 Keep 任务后产生的可消费权益。首版每名用户在每个活动中最多发放
一次；重复同步是幂等的，不会重复增加。

## LotteryDraw / 抽奖记录

消费一次抽奖机会后生成的不可变结果。机会扣减和结果写入必须在同一数据库事务中完成。

## PrizeClaim / 中奖领取信息

用户针对需要实物或权益发放的中奖记录提交的收件信息。同一中奖记录最多一条，领取信息与
不可变的抽奖结果分开保存。
_Avoid_: 中奖记录、发货记录

## ActivityPrize / 活动奖品

某个活动可抽中的结果，使用固定百万分比概率参与随机选择；`stock = -1` 表示不限库存。
需要用户提交领取信息的奖品标记为需要发放。

## PrizeProbability / 奖品概率

普通奖品在固定百万分比区间中的命中概率。概率不会因为其他奖品售罄而重新分配，修改后只
影响后续抽奖。

## FallbackPrize / 保底奖品

承接普通奖品概率之外全部剩余区间的奖品。普通奖品命中后库存不足时也降级为保底奖品；
它的概率由系统计算，不能单独设置。

## KeepClient

Keep 外部系统的防腐层，调用 Keep 用户资料和路线完成接口，并把外部协议隔离在活动领域之外。

## AnalyticsEvent / 行为事件

用户在前端发生的一次可统计行为，使用唯一事件标识去重。页面访问是 `page_view` 事件，
按钮点击和业务结果使用不同事件表达。

## Visitor / 访客

同一浏览器中的匿名访问主体；用户登录后，统计 UV 时优先使用系统用户身份。
_Avoid_: Session、用户
